- many deleted documentation files;
- modified deployment scripts;
- untracked top-level `analysis/`;

- untracked runtime/replay material.

Therefore the following operations are unsafe without a deliberate preservation/reconciliation plan:

```text
git reset --hard
git clean -fd
git checkout .
blind git pull
blind branch switching
```

Before any source deployment, inspect `git status`, understand which files are generated/runtime copies, and preserve any intentional server-only state.

## Safe modification rule

For persistent NIFTY dashboard changes:

1. Change the authoritative source under `nifty-options-paper-research/analysis/nifty_multi_shadow/` on the correct Git branch.
2. Test that source.
3. Deploy/synchronize deliberately into the runtime `analysis/nifty_multi_shadow/` location.
4. Verify runtime blob hashes.
5. Restart/reload only the relevant NIFTY runtime if required.
6. Confirm that regenerated `live_latest.html` contains the expected change.
7. Confirm the page through `127.0.0.1:8765/live_latest.html`.
8. Confirm the external tunnel surface separately.

Never make a permanent fix by editing the generated `live_latest.html`.
