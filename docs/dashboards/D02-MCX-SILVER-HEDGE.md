# D02 — MCX / Silver Hedge Research Dashboard

## What this is

D02 is the MCX / Silver hedge paper-research dashboard generated by the Silver hedge paper runtime.

It is a different application from D01 even though both are currently served through the same public Cloudflare origin.


## Data dependencies

D02 depends on mutable state under:

```text
/var/lib/hedge-engine/
```

including:

- strategy state;
- runtime checkpoint;
- ETF ledger;
- runtime health;
- execution history;
- price history;
- MCX scrip master;
- generated reports.

All audited MCX state is on the chartink-paper VM boot-volume filesystem unless separately backed up.

## Shared serving dependency

D02 shares its external serving layer with D01:

```text
Cloudflare Quick Tunnel
  -> 127.0.0.1:8765
  -> mcx_paper.control_server
```

The shared serving code is not the owner of D02 strategy/rendering.

## Security issue

The shared HTTP server also exposes a mutating MCX paper-control POST endpoint.

Current observed protection is a fixed `X-Paper-Control: local-dashboard` header plus an Origin check. That is not strong authentication for an Internet-facing origin.

No dashboard/UI change should make this control boundary broader.

## Repository decision

**Keep D02 in `kriskingg/hedge-engine`.**

The renderer and paper runtime consume the same Silver hedge domain state. Moving only the dashboard into another repo would create duplicated data/domain contracts without a current benefit.

The component that should be separated is the shared public serving/control layer, not D02 itself.

## Before changing D02

- [ ] Confirm `hedge-engine/main` HEAD and deployed SHA.
- [ ] Identify presentation vs strategy/control change.
- [ ] Change tracked source only.
- [ ] Run dashboard tests.
- [ ] Run paper/runtime/safety tests if data/control behavior changed.
- [ ] Verify primary `mcx_latest.html`.
- [ ] Verify published copy is identical.
- [ ] Verify local origin before public tunnel.
- [ ] Update registry/runtime SHA.
