# Dashboard Ownership Registry

This repository is the canonical ownership map for the dashboards operated across the user's trading/research systems.

The goal is simple: **never infer a dashboard's code ownership from its URL, hostname, page title, or repository name.** Every dashboard is traced end to end:

```text
Browser URL
  -> public/private ingress
  -> server/host
  -> listening service
  -> served/generated file
  -> runtime generator
  -> deployed working tree
  -> Git remote
  -> active branch + commit
  -> authoritative source path
```

## Rules

- Record only facts that have been verified from the running server and/or GitHub.
- Mark assumptions as assumptions. Do not silently promote historical lineage to current ownership.
- Do not store passwords, API keys, broker tokens, TOTP seeds, cookies, private SSH keys, session tokens, or other secrets here.
- A shared web server does **not** imply a shared application owner.
- A repository can own more than one runtime/dashboard.
- A deployed runtime copy may differ structurally from the authoritative Git-tracked source; document both.
- Before modifying a dashboard, identify its row in the ownership map and confirm the current branch/commit again.

## Why this registry exists

On 2026-09-18, the NIFTY and MCX dashboards were both exposed through the same Cloudflare quick tunnel and the same local HTTP/control service. This made it easy to incorrectly assume that the same codebase generated both pages. Investigation proved otherwise: the NIFTY page is generated by the NIFTY multi-shadow runtime from `etf-invest-engine`, while the local web/control server currently comes from a separate MCX deployment tree.

This repository exists to prevent that class of mistake.
